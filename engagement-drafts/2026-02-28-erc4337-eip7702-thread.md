## Thread (5 tweets)

### Tweet 1 (Intro)
ERC-4337 vs EIP-7702 isn't a competition — it's synergy 🔮

4337 gives you the infrastructure (UserOps, Paymasters, Bundlers)
7702 fixes the authorization layer (keep your EOA address)

Together → programmable accounts with native protocol support

Let's break down how they complement each other 👇

### Tweet 2 (ERC-4337 Mechanics)
ERC-4337 introduced application-layer account abstraction:
• UserOperations → separate mempool
• Bundlers → package ops via EntryPoint.handleOps
• 2-phase execution: validation → execution
• Paymasters → gas sponsorship

Adoption: 40M+ smart accounts, 100M+ UserOps, $10M+ sponsored gas

### Tweet 3 (EIP-7702 Mechanics)
EIP-7702 brings protocol-level delegation:
• New tx type 0x04 with authorization_list
• Temporary code pointer (0xef0100 || address)
• ~12.5k gas (significantly cheaper than 4337 or EOA transfers)
• Your EOA → smart contract logic for one transaction

Shipped with Pectra hardfork (May 2025)

### Tweet 4 (The Synergy)
Why they work together:

7702 → solves "I don't want to lose my address" problem
4337 → provides the powerful functions (batching, recovery, session keys)

Real workflow:
1. User authorizes smart contract code (7702)
2. Intent → UserOperation → Bundler (4337)
3. Paymaster covers gas in USDC (4337)

### Tweet 5 (Implications for Permissions/Delegations)
This is where ERC-7710 (delegation interfaces) and ERC-7715 (permissions) become critical:

• 7702 handles *authorization*
• 7710 defines *what* can be delegated
• 7715 specifies *session permissions*

The stack is coming together → flexible, secure, user-friendly smart accounts 🚀
