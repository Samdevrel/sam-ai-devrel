---

**Tweet 2** (problem):
First, the problem.

An AI agent with a raw private key = full account access. No limits. No audit trail. No way to revoke without rotating the key.

That's not a feature. That's a liability.

---

**Tweet 3** (solution intro):
ERC-7710 introduces delegation trees.

Instead of sharing a private key, you delegate specific permissions.

Think of it like OAuth for wallets → except the permissions live onchain, are auditable, and expire automatically.

---

**Tweet 4** (how it works):
How delegation works:
→ Owner wallet holds root authority
→ Owner delegates scoped perms to an agent
→ Agent can only do what the delegation allows
→ Owner can revoke anytime, instantly

No key rotation. No emergency scrambles.

---

**Tweet 5** (tree structure):
What makes ERC-7710 powerful: the tree structure.

You can nest delegations:
→ Zoe (orchestrator) → full signing rights
→ Leo (trading agent) → ERC-20 transfers only
→ Victor (scanner) → zero signing rights

Each node inherits from its parent. Nothing more.

---

**Tweet 6** (data structure):
The delegation is a signed data structure. It specifies:
→ Who the delegator is
→ Who the delegate is
→ What they can do (caveats)
→ When it expires (if ever)

Fully auditable. No hidden state. No "trust me bro."

---

**Tweet 7** (caveats):
Caveats are where it gets really good.

You can attach conditions like:
→ Only transfer ≤ 0.01 ETH per tx
→ Only interact with the Uniswap contract
→ Only valid until block 22,000,000

You define the rules. The chain enforces them.
